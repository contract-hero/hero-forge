hero-forge daily reconcile for <<repo>>. Start the work a missed webhook should have started: one thread per decision that is not `ignore`. Run only the steps below: no other command, no edits, no questions. End with one line, as step 7 says, and the last two steps come before it.

1. Find the helper CLI: `node -p 'require(process.env.HOME + "/.claude/plugins/installed_plugins.json").plugins["hero-forge@contract-hero"][0].installPath'`. Below, `review.ts` means `node "<that path>/skills/engineering/review-pipeline/scripts/review.ts"`. A failure: exit with `stop: hero-forge is not installed`.
2. Find the local clone of <<repo>>, as a T3 project. List the projects with `t3_project_list` (every page). The clone is the project that is not deleted and whose `repositoryIdentity` names <<repo>>, or whose `git -C <workspaceRoot> remote get-url origin` is <<repo>> on github.com. No project: exit with `stop: no T3 project for <<repo>>` (the router registers or clones it on the next delivery).
3. Mark the threads of ended AFK runs unread: an AFK run that needs the maintainer cannot mark its own thread, so it puts the thread on the unread list. In that project's `workspaceRoot`, run `review.ts unread list`. It prints zero or more lines, each `{thread, added_at}`. For each line, call `t3_thread_organize` with action `mark_unread` and `threadId` the `thread`. When it succeeds, or fails with `thread_not_found` (the thread is gone), run `review.ts unread done --thread <thread>` in the `workspaceRoot`. When it fails because the thread has no completed run (the run has not ended yet), keep the line: the next sweep tries it again, and this is not a failure. When it fails with any other error, also keep the line, and keep the error as an unread message for step 7. A non-zero exit of `unread list` (a corrupt record, which no sweep repairs: its stderr names the file to delete) still marks the lines it printed, and its message is an unread message too. Go on with step 4.
4. In that project's `workspaceRoot`, run `review.ts reconcile --repo <<repo>>`. It prints zero or more lines, each one decision as JSON: `{action, repo, pr, issue, reason, lock_token, app}`. A non-zero exit before any line: exit with `stop: <its message>`. A non-zero exit after some lines: still start the lines it printed (they hold their locks), then say the message in the last line.
5. For each line whose `action` is not `ignore`, pick the launch message, with `<n>` the `pr` or the `issue` of the decision, its base and its worker model:

   | action | message | base | worker model |
   | --- | --- | --- | --- |
   | `review` | `/hero-forge:review-pipeline <pr> --afk review --lock <lock_token>` | the PR head | `<<light_worker_model>>` |
   | `adjudicate` | `/hero-forge:review-pipeline <pr> --afk adjudicate --lock <lock_token>` | the PR head | `<<worker_model>>` |
   | `recheck` | `/hero-forge:review-pipeline <pr> --afk recheck --lock <lock_token>` | the PR head | `<<light_worker_model>>` |
   | `resume`, `pr` set | `/hero-forge:review-pipeline <pr> --afk adjudicate --resume --lock <lock_token>` | the PR head | `<<worker_model>>` |
   | `build-ticket` | `/hero-forge:implement-pr <issue> --afk --lock <lock_token>` | the default branch | `<<worker_model>>` |
   | `build-spec` | `/hero-forge:implement-spec-stack <issue> --afk --lock <lock_token>` | the default branch | `<<worker_model>>` |
   | `resume`, `issue` set | `/hero-forge:implement-pr <issue> --afk --resume --lock <lock_token>`; `implement-spec-stack` in place of `implement-pr` when `gh api repos/<<repo>>/issues/<issue> --jq .sub_issues_summary.total` is more than 0 | the default branch | `<<worker_model>>` |

   The PR head: `gh pr view <pr> --repo <<repo>> --json headRefName --jq .headRefName`. The default branch: `gh repo view <<repo>> --json defaultBranchRef --jq .defaultBranchRef.name`.
6. Launch one thread per such line with `t3_thread_launch`: `projectId` the project of step 2, `title` `<app> <action> <<repo>>#<n>`, `workspaceStrategy` `{type: "worktree", baseRef: <base>, startFromOrigin: true}`, `modelSelection` `{instanceId: "claudeAgent", model: <the worker model of the table>}` (always set it: the worker runs Claude Code plugin commands, so it must not take the model of this thread), and `message` the message of step 5. A launch that fails: give back what its decision took, `review.ts route undo --app <app> --token <lock_token>`, in the `workspaceRoot`, so the next sweep decides it again; count it as failed.
7. Exit with one line: `reconcile: started <count>, ignored <count>, failed <count>`, then the non-zero exit message of step 4, if any, then each unread message of step 3, if any.
8. Every exit above: before step 9, remove this thread's own worktree: call `t3_worktree_status`. When `attached` is true and its `worktreePath` is not its `projectWorkspaceRoot`, run `git -C <projectWorkspaceRoot> worktree remove --force <worktreePath> && git -C <projectWorkspaceRoot> branch -D <branch>`, with the three values it gives. T3 starts each run of this task in a new worktree, and this run edits nothing in it, so it holds nothing to keep (`--force` also removes what the project's setup script wrote there). This is the last shell command of the run: after it, only step 9 and the exit line. A failure changes nothing: the exit line stays as it is.
9. Every exit above: as the last action, before you write its line, call `t3_thread_organize` with no `threadId`, which acts on this thread. Use action `settle` (it takes effect when this turn ends; `archive` would cut the turn) for a `reconcile: started ...` line with `failed 0`, no message of step 4 and no unread message of step 3: the thread holds nothing for the maintainer. Use action `mark_unread` for a `stop: ...` exit, and for a `reconcile:` line with a failed launch, a message of step 4 or an unread message of step 3, so the maintainer sees it. A session with no `t3_thread_organize` tool skips this step.
